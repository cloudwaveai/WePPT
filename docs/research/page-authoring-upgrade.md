# 页面设计链路升级

本次范围：结构化内容、完整原生页面、发布前实际渲染与一次模型看图检查。

- 整稿计划可保存统一配色/字体和每页 composition：表达目的、关系、完整内容组。
- slide_add 可携带完整 scene，与 diagram 二选一。服务器分配实际页 ID，检查标题和内容覆盖；作者页面不会再被默认模板重排。
- 旧协议继续兼容，结构化计划的页面必须提交完整布局。
- 生成页保留所有内容组，不能用缩写、不可见文本或遗漏替代。默认基础渲染不再插入项目主题页脚；已有用户页面不变。
- Codex 的新页面先由 Chromium 在服务器渲染为原始 PNG，记录字体与文字溢出，再把截图和内容方案交给模型检查。一次看图修正只能改变设计，文字/原始图片清单必须保持，修正后再次渲染。
- 渲染只接收现有已校验的 scene；HTML 文本转义、图片为本地 data URL，不执行模型代码、不访问外部素材网址。浏览器随调用结束，不常驻。
- 看图不代替用户验收；保留初稿、截图及报告。看图调用失败时保留初稿并提示未完成；明确文字溢出时最多重新生成两次。Claude 当前未接入截图检查，不能声称完成看图。
- 此轮不扩展动画、原生数据图表和任意 SVG 导入，也不宣称已复现 PPT Master 全部能力。

实际验证见 `../../validation/page-design-2026-10-30/summary.md`。新页支持 textRef 引用已存内容组，模型只设计布局，服务器补齐原文字。生成协议/标题绑定/图解审图上下文问题经真实失败修正；不以单元测试替代整稿实测。最终 8 页已导出和逐页渲染，但发生重试、仍有审美问题，不能声称稳定 one-shot。
