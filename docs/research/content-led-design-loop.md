# 内容驱动的设计循环

2026-10-30。用户要求模板是参考、能依内容变通，并使用生成—检查—修改—总结循环。

## 诊断

- 模板库截图展示固定示例本身正常。问题在运行时：template_adaptation 原先从 Studio.context 只挑选 project/currentPage/scene/sceneSpec/rules，丢失 diagramDesign、pageExpression 和 visualGuidance。
- 原默认 faithful，提示词要求保留分区比例、标题位置和可辨认构图。即使换模型，也会被相同指令引向模仿。
- 绘图 skill 已部分接入：diagram_design 的四种固定编译器负责几何，而 agent_bridge 又要求优先使用它。完整原生 scene 已经支持自由作者布局，但没有成为默认设计路径。
- 模板适配检查只看内容完整性与实际溢出；新页设计检查只对 Codex 看图。协议重试不是设计质量循环。
- 原来没有基于已应用结果的项目内经验检索。换模型或扩大模板库不能单独修复这些编排问题。

## 本轮实现

1. 自由设计为默认。模板提供配色、字体、主次和图形语言；按本页内容选择分区、节点和连接。精确模仿仍是用户可选模式。
2. 模板与新页都接收 diagram-design 类型指导。根据内容选择 loop、architecture、layers、comparison 或 process；完整 scene 为首选，固定四类编译器只作适配时的快捷方式。
3. 新页与模板预览共用 design_loop。实际渲染 → 检查 → 至多一次修正 → 再渲染与复核；复核不再启动下一轮重排。支持看图的模型读原始 PNG，其他模型只读结构并明确标记。
4. 原文、原图、页面范围及版本保护继续生效。修正引入新机械错误或改变文字/图片时保留先前候选并标记 needs_attention；未通过实际溢出检查的候选不能发布。
5. 保存每次检查的模型结论、测量、截图哈希、加载的 skill 来源、修正事实与剩余问题。自动 PASS 仅表示模型检查结果，不表示用户验收。
6. 项目内同类内容可检索至多 3 条已应用且仍为当前场景的方案，复用已观察到的字号/底色和机械纠错记录。未应用、撤销、已被替换的方案不进入经验。没有后台自改系统提示词、自动训练或跨项目传播。

## 成本与边界

找模板仍为本地筛选，零模型调用。选定后的设计除了初稿调用，最多增加两次检查调用；有明确次数和时间上限。只有确定的内容/协议错误进入原有最多三次生成纠错。

此版接入的是绘图方法与可编辑原生场景，仍受 scene 的 text/rect/line/image 原语限制，不等于完整 SVG 工具链或所有 45 种图形已实现。固定 diagram 的既有生图兜底继续保留；自由 scene 不冒充该编译器的图解元数据。原文字对象暂保持完整，不自动拆分/合并原文或改写事实。

本轮共用循环覆盖自动整稿新页与模板适配预览。局部文字工具、手工编辑、本地大纲模式不强制进入多次模型调用。整稿反馈的普通 patch 路径仍沿用原校验，不宣称所有编辑入口都接入设计循环。

验收以运行证据为准：validation/design-loop-2026-10-30/。


## 真实调用发现的修正

首轮候选已改变原模板构图，但图型指导错误地读取旧页面说明；现已改为读取当前画布实际文字与备注。检查输出从完整场景优先改为候选上的 scene_patch / scene_objects，以减少重复输出；仍做完整内容与作用域检查。

两次真实调用出现输出截断，截断结果均未应用。官方 DeepSeek Flash 默认 high 思考，而本服务的输出上限为 16384；本版仅对该官方模型的 template_adaptation / deck_page / design_loop_review 任务显式指定 low，保持模型身份与原上限。依据：https://api-docs.deepseek.com/guides/thinking_mode/ 。不对其他供应商猜测参数，不保存模型推理正文。


真实检查还发现：新方向箭头曾被内容保护误当成新增正文。现将单个 ← → ↑ ↓ ↔ ↕ 作为可编辑连接符号，允许修正添加；新增业务文字、替换图片、删减正文仍拒绝。检查动作保存在报告中，便于追溯被接受或拒绝的具体修正。复验直接使用已保存候选，不再次生成初稿。

## editor-42：语义优先及原生线端点

真实复验进一步发现，上游 Loop 指导本身要求共享中心，普通反馈流程被错误地套成中心图。普通反馈现使用项目 adaptation，明确共享状态时才建议 hub-loop；原文、备注与保存的内容方案作为独立语义依据，优先于候选几何和图型。复核收到上一轮意见，仍保持最多一次修正。

方向符号虽然可以通过内容保护，却容易与线条错位。新 line.startArrow/endArrow 为原生可编辑端点，网页与 PPTX 导出同步支持；模型默认使用这些端点，旧符号仍可读取。实际样例已经修正主路径和反馈返回点，并通过两次调用内的修正与复核；这是对已保存候选的优化，不是全新 one-shot 实验。证据：`validation/semantic-flow-2026-10-30/summary.md`。
