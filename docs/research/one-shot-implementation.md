# 整稿 one-shot 实施与验收（2026-10-31）

用户目标：一次需求输入，内部完成内容策划、设计、生成、看图、限次修正，交付可编辑整稿；模板为参考，保留事实、原文、原图和手改。

## 本次必交付

- 整稿 strategy：受众、目标、叙事、视觉语言、字体层级、图片原则、节奏；内部比较不同视觉方向并选定。
- 模型草稿锁定前做一次策划复核：检查用户要求覆盖、证据边界、密度与多余制作说明；保存初稿与修订记录。内部使用稀疏字段修改，避免重复输出整稿导致截断。
- 每页 designBrief：主张、证据、具体图像/图解表达、阅读路径、密度和连续关系；内容分组在此之后。
- 生成上下文包含整稿设计清单、前页实际布局、内容匹配的模板参考及 diagram-design。
- 原文可无损分布到多个文本对象，范围校验拒绝遗漏/重叠；旧页面和用户编辑保持。
- 全页生成后自动实际渲染整稿，原生分辨率拼图检查；最多两轮、合计三次页面定向修正，最后整稿复核；调用与修正次数持久保存。
- 修正采用前验证原始项目和页面版本，原文/原图/图解关系保护；暂停、取消、恢复和模型绑定保持。
- UI 显示整稿检查状态和未通过原因，不把模型通过当人工验收。
- 同题完整新稿实测：无需逐页人工修复；导出 editable PPTX 后实际渲染、逐页查看，记录内容、设计、调用与耗时及失败。
- 验证后发布既有开发环境并验证实际运行文件与浏览器。

## 非本次范围

不替换整个编辑器、不引入任意 HTML 运行、不做模型训练；成功经验只复用当前项目真正被用户采用且仍有效的方案。生图仅沿用用户触发的现有降级通道，不擅自把整页变为图片。原生图表/表格组件是后续扩展；本次使用已有可编辑文本、图形和连线。
