# 图片生成失败修复 · 2026-10-29

已恢复。沿用用户原 key、原模型和原网关，真实生成 PNG，并完成 main 项目 S001 封面右侧的原生图任务。没有替换凭据、修改网关权限或伪装客户端。

## 根因与证据

1. 原部署只投影了模型、base_url、env_key 等文字调用配置，遗漏了网关要求的非秘密生图标识：`model_providers.weppt.http_headers.x-openai-actor-authorization = "aiseat"`。
2. 16:39 原任务的数据库记录为 failed，asset_id 为 NULL，项目素材列表为空。原适配器吞掉了失败类别；前端却统一显示“已生成图片保存在项目中”。
3. 用原参数复现时，官方 Codex CLI 退出码为 0，但只返回 `{"path":""}`，没有图片工具调用或文件。会话能力检查报告没有 image_gen。
4. 对照服务器原有完整 Codex 配置和网关 `/key` 页手动配置说明，确认遗漏标识。使用完整配置的隔离检查出现 `image_gen__imagegen`。
5. 仅向 WePPT 配置补上该标识后，原 key 真正生成图片，耗时 42.13 秒，原始 PNG 为 1,636,894 字节。原文件 SHA-256：`d7241e41e9f5b98bcc0838f9713519af7c5ada9d76149d4853c2211dcbb20244`。

早先“图片能力尚未接通”的中间结论已由上述实测更新；这不是原 key 不支持生图，而是部署时漏带了该网关的工具配置。不能仅凭文字调用可用或模型列表只有文字模型判断图片工具能力。

## 已修改

- 代码版本 `20261029-editor-05`：状态返回实际生成数量、总数和安全错误类别；空路径、工具不可用、超时等不再被混为已有图片。
- 新错误表只保存固定代码，不保存供应商原文或凭据。
- WePPT 的 Codex 持久配置补上网关标识；文本规划仍禁用工具，图片任务仍通过官方 Codex 客户端调用。
- 配置投影准备脚本和部署说明补充该字段，避免重新部署时再次丢失。
