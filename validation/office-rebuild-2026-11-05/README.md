# Office 操作与设计规则重构 · 2026-11-05

本轮是用户会议反馈后的直接重构，不重开 T1–T8，也不覆盖旧任务卡结论。改动在本地工作目录；线上仍为 editor-68，尚未发布本轮修改。`DEPLOYMENT.md` 原有未提交修改保持。

## 已验证的行为

- 左侧 `＋` 紧接当前页插入，无需提示词、无需模型；复制、上移、下移、删除和恢复。
- 配色默认应用到整稿；一次撤销恢复全部改变页面、已应用的颜色映射和未来生成的配色设置。操作与读取均核验版本。
- 参考风格支持 1–3 张图；可粘贴、拖入或上传。原图保留。上传后自动排队分析并创建风格副本；缺少看图能力会报告真实原因，参考图仍保留。
- 改版准备为数据库持久任务；页面关闭不取消；重启重新打开待处理项目，运行中断明确记失败，不偷偷重复创建副本。源稿变化时拒绝基于过期版本改版。
- 输入草稿按项目保存到本机；项目列表显示生成状态。已有 PPTX 可从工具栏或受众版本入口打开到新项目，并下载逐字节一致的原稿。
- PPTX 导入解析全部页面再创建项目。测试稿全部文字、讲者备注、页数和原图字节通过往返检查。
- 统一设计规则已接入策划、生成、单页适配及检查。取消为了达到大字号比例而自动放大数字的整稿行为，保留内容、图像、越界、可读性及版本保护。几何指标仍提供给审稿模型作证据。

2. 文档级新增/删除/移动/整稿配色目前支持最近一次撤销；尚不是 Office 完整多级撤销栈。既有单页文字编辑保留撤销/重做。
3. 受众/风格副本原有附件上限仍是 10 张、单张 8 MB；现在超限先拒绝，不再默认丢图继续生成。
4. 未做 PowerPoint 桌面实机兼容测试、线上真实浏览器重构验收或本轮发布。素材筛选站未修改。

### 实物检查后的内容保护修正

诊断重试最终 3/3 完成（256.97 秒、人工重试 1 次、原稿未改），但不能验收：逐字读回发现源第 3 页两处“开发中”只剩一处，且渲染可见该标记仅覆盖左侧功能；右侧功能失去了开发状态限定。`restyle-diagnostic/sample.pptx` 仅作失败证据，不作为推荐交付样稿。三页已实际渲染查看，几何测量 3/3、溢出 0 并未发现这个语义缺陷。

根因是 `derived._source_pages` 把可见原文按字符串去重。已改为保留重复文本；新建改版副本时冻结 `restyle-source.json`，在整稿计划和每页落库前核对原文出现次数、页数和页序。缺少重复限定词时阻止应用，并把缺失明细反馈给模型作有界纠正。原文计数不能代替对限定对象的语义与视觉检查，也不追溯修改旧稿。受众版本允许的明确删改仍沿用其独立规则。

另补原稿页面的副本真实进度/失败状态。Linux Python 3.11 实测发现通用 owner 可见性辅助函数在状态读取中初始化表，导致 SQLite savepoint 提前提交；新路径改为只读已初始化的 owner 表。保留准备阶段失败日志于 `restyle-guarded-preparation/`，未影响现役服务。

补测期间新增反例的第一版 fixture 只有 1 页，先被既有“整稿至少 2 页”校验拒绝，断言未到目标路径；已改为合法 2 页输入，原失败 `source-protection-final.log` / `python-final-guarded.log` 保留。修正后的定向测试见 `source-protection-recheck2.log`。
