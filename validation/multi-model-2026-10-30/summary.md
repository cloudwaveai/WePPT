# 多模型接入验收 · 2026-10-30

现役开发环境：https://ppt.bbstack.date/ ，镜像 `weppt-dev:20261030-editor-33`。

## 可用入口

顶部模型菜单：按项目选择模型，刷新后保持；每条新任务、整稿子页和反馈子任务保存同一模型绑定。轮次结果显示模型。浏览器只发送服务器配置 ID，未接收密钥或地址。API 密钥仅保存于服务器的权限受限环境文件。

9 个配置全部完成真实连接调用：六个 GPT 网关模型 + 同网关 gpt-6-luna 的 Claude Code 兼容通道 + DeepSeek 官方 deepseek-flash/deepseek-v4-pro。网关返回的模型标识不等于独立验证的上游模型身份。Claude Code 客户端不代表使用 Claude 模型。

## 实测

- Mac/Linux：基础相关 162 项通过；后续字段协议修正相关 88 项各通过；前端 42 项通过。
- 两个 DeepSeek 模型与 Claude Code：合成样稿的指定标题修改、完整渲染、字体就绪且无溢出通过。
- DeepSeek Flash：整稿反馈分派、单页修改、原文逐字一致、其他对象样式及其他两页保持通过。
- 线上 Chrome：模型列表、选择保存、刷新、DeepSeek 页面编辑、轮次模型标注、快捷推荐前后预览和取消均通过；浏览器无脚本错误。三个截图已实际打开检查。
- 原用户项目保持 8 页、4 轮；34 行场景历史与发布前数据库逐项一致。
- 测试项目：https://ppt.bbstack.date/?project=project-6f457f2bfe67c5f6 。仅演示数据；当前选择 DeepSeek V4 Pro，可自行切换比较。未做人工认可或正式交付确认。

## 实测边界与保留失败

- 第一条合成测试使用未加引用的目标文字，模型把指令中的句号一并作为标题；明确 JSON 引用后逐字一致。测试不据此声称模型能猜中不明确的标点边界。
- 线上最初的整稿反馈用了不合法字段路径，未应用；editor-33 增加明确合法字段说明和最多三次协议纠错。测试过程中还出现一次 `SCENE_STALE`，原稿保持；对同一轮重试后成功。不能据这次验收承诺所有模型都能一次生成成功。
- 目前 DeepSeek API、Claude Code 通道只处理文字与页面结构，不传入图片像素，不声称完成看图审阅；Codex 保持原看图通道。生图与 JEV 选版配置独立。
- 所有检查验证本次接入、编辑和状态保护；不是整套 PPT 审美评测，也未代用户验收。
